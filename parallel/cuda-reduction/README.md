# CUDAリダクションの7段階の最適化

Multi-core GPU Programming（2024年春）課題5。CUDA。

## 方法

共有メモリを使う総和カーネルを、次の順に7段階で書き換え、それぞれを入力サイズ別に測った。

1. 交互アドレッシング（分岐が多い版）
2. 交互アドレッシング（`%` を除いた版。共有メモリのバンクコンフリクトが起きる）
3. 逐次アドレッシング（バンクコンフリクトを避ける）
4. グローバルメモリからの読み込み時に最初の加算を行う
5. 最後のワープを展開する（`volatile` を使い `__syncthreads()` を省く）
6. テンプレートでブロックサイズを固定し、ループを完全に展開する
7. 1スレッドで複数の要素を足す（グリッドとブロックのサイズを指定した版も用意）

ブロック数がブロックサイズより大きい間はカーネルを繰り返し呼び、各ブロックの部分和をさらに足し合わせる。

## 結果と考察

- 入力が 16,777,216 要素のときは2段階目が最も速かった。64要素と16,384要素では4段階目が速く、大きい入力でも2段階目との差が小さかったので、4段階目を採用した。
- 理論上は速くなるはずの5〜7段階目が、自分の実装では速くならなかった。原因は、カーネルを繰り返し呼ぶ構造にあると考えた。入力が小さくなるとブロックサイズも小さくなり、1ブロックで多くを処理する工夫が効かなくなる。
- 7段階目で、グリッドとブロックのサイズを指定した版の方がはるかに速かった。自分の実装では、カーネル内の工夫よりも起動構成（グリッド・ブロックのサイズと呼び出し回数）の影響の方が大きかった。
