# ロック付きハッシュテーブルの高速化

Multi-core GPU Programming（2024年春）課題2「To lock or Not to lock」。C++、std::thread。

## 課題

配布されたロック付きのプロービング方式ハッシュテーブル（ベースライン）を、オープンアドレス法の範囲で高速化する。`main.cc` と `bucket.h` は変更不可で、自分の実装は `better_locked_hash_table.h` に書く。

## 方法

- **二重ハッシュ法**：線形探索では、ハッシュ値が同じか近いキー同士が同じ位置を何度も探索する。キーごとに2つ目のハッシュ関数で探索間隔を変え、衝突の連鎖を減らした。
- **細粒度ロック**：表全体を1つのロックで守るのではなく、ロックの配列（500万個）を用意し、書き込むバケットのロックだけを取る。読み出しはロックを取らない。
- 探索が一周して元の位置に戻った場合（表のサイズが探索間隔で割り切れる場合）は、隣のバケットに移って探索を続け、すべての位置を確認できるようにした。

## 測定

- 条件：16スレッド、初期挿入400万件、その後に挿入1回と読み出し9回の組を合計3,600万回
- `make` で10回実行し、ベースラインと自分の実装の平均・中央値を比較

| 区間 | ベースライン比（平均） | ベースライン比（中央値） |
| --- | --- | --- |
| 初期挿入 | 17.2倍 | 17.5倍 |
| テスト（挿入＋読み出し） | 17.7倍 | 18.2倍 |
